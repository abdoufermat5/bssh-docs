## Des agents IA qui demandent avant d'agir

bssh AI relie Claude Code, Codex, Cursor et d'autres agents à vos hôtes via un serveur MCP local. L'agent n'a jamais de clé et n'ouvre jamais de shell. Les lectures s'exécutent tout de suite, dans un bac à sable en lecture seule. Tout ce qui modifie un hôte vous attend, puis s'exécute exactement comme approuvé.

```text frame="terminal"
$ bssh ai install claude-code
$ bssh ai explain --host web-1 "journalctl -u nginx -n 50" | tail -1
decision: allow - analyzer: every command is read-only
$ bssh ai explain --host web-1 "systemctl reload nginx" | tail -1
decision: deny - profile.observe: the observe profile cannot change anything
```

Par défaut, les agents ne peuvent que lire. Une entrée de politique les laisse proposer des modifications, et vous approuvez chacune.

## Sécurisé dès la conception

Chacun de ces points est appliqué par bssh lui-même, pas laissé aux bonnes pratiques.

<CardGrid>
	<Card title="Vos clés restent les vôtres" icon="padlock">
		bssh utilise vos clés et votre agent SSH là où ils sont. Les agents IA n'ont jamais de clé, et aucun relais ne s'interpose entre vous et vos serveurs.
	</Card>
	<Card title="Des décisions lisibles" icon="list-format">
		Un analyseur de shell et votre politique décident de ce qu'un agent peut exécuter. Aucun modèle n'intervient, et `bssh ai explain` montre le résultat à l'avance.
	</Card>
	<Card title="Une personne approuve les modifications" icon="approve-check">
		Les modifications attendent une approbation, avec la commande et le diff exacts. Avec l'autorité de certification locale, une commande approuvée s'exécute avec un certificat valable pour elle seule.
	</Card>
	<Card title="Un journal vérifiable" icon="document">
		Les appels des agents et les sessions d'équipe vont dans des journaux signés et chaînés, que vous pouvez vérifier sur votre propre machine.
	</Card>
	<Card title="Partage chiffré de bout en bout" icon="link-alt">
		bssh Teams chiffre les connexions partagées sur vos appareils. Le serveur de synchronisation ne voit jamais hôtes, utilisateurs ni clés.
	</Card>
	<Card title="Versions signées" icon="approve-check-circle">
		Chaque version est signée et accompagnée de sa provenance de build. L'installateur vérifie les sommes de contrôle, et la signature quand cosign est installé.
	</Card>
</CardGrid>
