## 先询问、再行动的 AI 智能体

bssh AI 通过本地 MCP 服务器把 Claude Code、Codex、Cursor 等智能体连接到你的主机。智能体从不持有密钥，也不会打开 shell。读取操作立即在只读隔离环境中执行。任何会改动主机的操作都要等你批准，并严格按批准的内容执行。

```text frame="terminal"
$ bssh ai install claude-code
$ bssh ai explain --host web-1 "journalctl -u nginx -n 50" | tail -1
decision: allow - analyzer: every command is read-only
$ bssh ai explain --host web-1 "systemctl reload nginx" | tail -1
decision: deny - profile.observe: the observe profile cannot change anything
```

默认情况下，智能体只能读取。添加一条策略即可允许它们提出变更，由你逐一批准。

## 安全源于设计

以下每一项都由 bssh 本身强制执行，而不是依赖良好习惯。

<CardGrid>
	<Card title="密钥始终属于你" icon="padlock">
		bssh 直接使用你现有的 SSH 密钥和 agent。AI 智能体从不持有密钥，你和服务器之间也没有任何中转。
	</Card>
	<Card title="看得懂的判定" icon="list-format">
		由 shell 解析器和你的策略决定智能体能执行什么，没有模型参与，`bssh ai explain` 可以提前显示结果。
	</Card>
	<Card title="变更由人审批" icon="approve-check">
		变更需等待审批，并显示确切的命令和 diff。使用本地 CA 时，获批的命令以仅对该命令有效的证书执行。
	</Card>
	<Card title="可验证的记录" icon="document">
		智能体的调用和团队会话都写入签名的哈希链日志，你可以在自己的机器上验证。
	</Card>
	<Card title="端到端加密共享" icon="link-alt">
		bssh Teams 在你的设备上加密共享的连接。同步服务器永远看不到主机、用户名或密钥。
	</Card>
	<Card title="签名的发布版本" icon="approve-check-circle">
		每个版本都经过签名并附带构建来源证明。安装脚本会校验校验和，安装了 cosign 时还会校验签名。
	</Card>
</CardGrid>

## 日常 SSH，一键直达

<DemoVideo label="演示：从 ~/.ssh/config 导入主机，模糊匹配连接，经堡垒机连接，在多台服务器上同时执行命令和上传文件，查看会话历史，然后在桌面应用中打开两个实时终端并使用命令面板。" />

```sh frame="terminal"
curl -fsSL https://bssh.abdoufermat.dev/install.sh | bash
bssh add web-prod web-prod.example.com --tags prod,web
bssh connect prod
```

<CardGrid>
	<Card title="找到你想要的主机" icon="magnifier">
		输入名称的一部分、一个标签或缩写即可。结果按你使用每台主机的频率和最近程度排序。
	</Card>
	<Card title="内置跳板机与 Kerberos" icon="server">
		跳板机、交互式堡垒机和 Kerberos 票据都会自动处理，可按连接设置，也可设为默认。
	</Card>
	<Card title="命令行与桌面" icon="laptop">
		`bssh` 和桌面应用共用同一份主机列表，并提供终端、文件传输和会话历史。
	</Card>
	<Card title="会话有据可查" icon="notes">
		每次会话都会记入历史，包括时长和退出码。开启录制后，还能回放和搜索当时发生的一切。
	</Card>
</CardGrid>
