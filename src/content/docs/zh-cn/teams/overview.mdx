bssh Teams 可以与你的工作伙伴共享连接。每个人都可以在 `bssh` 和桌面应用中获取相同的主机列表，再也不需要在聊天工具或维基文档中互相传阅服务器列表。

共享连接在离开你的设备前就已经在本地完成加密。同步服务器仅保存密文和少量的元数据：它永远看不到主机名、用户名或标签，并且绝不会进入你的 SSH 连接网络路径。

## 工作原理

1. **每台设备拥有独立的密钥。** 配置 Teams 会在你的机器上生成由口令保护的签名密钥与加密密钥。它们绝不会离开你的设备。
2. **一个团队拥有一份团队密钥。** 管理员在核对新设备的指纹后将其授予该设备，从而杜绝服务器擅自混入其自有的设备。
3. **条目在本地加密。** 共享某个连接时会使用团队密钥对其进行加密。服务器保存加密结果并分发给成员。
4. **团队成员在本地解密。** 每次同步都会拉取新条目，验证其作者身份，并将其以 `name@team` 的格式添加到你的主机列表中。
5. **连接行为经过审计。** 连接到团队主机时会记录一条经过签名且哈希成链的事件。管理员可以在自己的设备上验证整条审计日志。

## 共享的内容

共享连接包含其主机地址、用户、端口、跳板机、Kerberos 设置及标签。

以下内容绝不会被共享：

- **密钥、密钥路径与密码。** 每个人都使用自己的凭据或本地代理进行连接。
- **你的设备密钥与口令。**
- **会话录制内容与终端输出。** 它们只保存在你的机器上。
- **未共享的连接。** 个人主机始终保存在本地数据库中。

## 方案

- **免费版：** 在托管服务上，每个[组织](/zh-cn/teams/organizations/)免费拥有 3 个席位，由其团队共享，可使用所有功能。
- **付费版：** 若需要更多席位，组织所有者可按月或按年为整个组织订阅，按席位计费。
- **自托管：** 自行运行同步服务器；每个组织的席位限制由运维方设定。

详细信息请参阅[方案与计费](/zh-cn/teams/plans-and-billing/)。如需在托管服务上创建团队或咨询自托管事宜，请[在 GitHub 上提交 issue](https://github.com/abdoufermat5/bayesian-ssh/issues)。
